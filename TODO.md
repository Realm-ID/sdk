# sdk/ — punch list

- [ ] `java/src/main/java/dev/realmid/sdk/.../HttpTransport` (+ `TenantsClientTest`) — Java SDK still bootstraps platform auth via `POST /auth/platform-token`, which was hard-cut in server v0.7.0 (ADR-051). Migrate to the two-endpoint flow (`POST /auth/login {grant_type:"platform_api_key"}` + `POST /auth/token`) like the Go/TS SDKs already do.
- [ ] `ts/src/auth.ts` — BFF on-behalf-of parity. The TS current-user session/MFA methods (`revokeSession`, `listSessions`, and the new `revokeAllSessions`/`enrollMfa`/`confirmMfa`/`disableMfa`, SPEC §4.5–4.10) accept only a direct `userBearer`; Go and Java also support BFF mode (`userId` + platform token + `X-On-Behalf-Of-User`). Add the on-behalf-of header path to the TS HttpClient + these methods for cross-language parity.
- [x] **Long-lived-client token manager** (SHIPPED 2026-05-28, SPEC §4.2.1) — `NewTokenManager`/`newTokenManager` + `RefreshSink` (persist-before-return) + single-flight live in `go/token_manager.go` and `ts/src/token-manager.ts`. Auth model: own API key → issuer direct (wraps `Auth.Token`). Java pending — see Java-parity item below.
- [x] **Typed dead-refresh error code** (SHIPPED 2026-05-28, SPEC §3.1) — single `refresh_invalid` emitted by issuer `/auth/token` (gToken maps `ErrNotAuthenticated`) and surfaced as `ErrCodeRefreshInvalid` / `"refresh_invalid"` in Go+TS. Not split into expiry/reuse (issuer doesn't distinguish on the wire). Requires issuer ≥ v0.12.0. Java pending.
- [ ] **Java parity: token manager + refresh_invalid + api-key DTO** (2026-05-28) — Java SDK (`java/`) was NOT bumped in the v0.8.0 SPEC lockstep. It lacks: `refresh_invalid` error code, the `TokenManager` construct (SPEC §4.2.1), and the api-key DTO alignment (list `role`/`prefix`/unix-second timestamps; create one-time `value`). Implement to restore lockstep, then bump `java-v0.10.0`. (Note: Java also still owes the ADR-051 platform-token migration above.)
- [ ] **`ui/sdk-ts` drift** (2026-05-28) — `ui/sdk-ts/` is a mirror of `sdk/ts/` (`ui/CLAUDE.md`: "do not let them drift"). The v0.8.0 TS changes (token manager, `refresh_invalid`, api-key DTO) landed in `sdk/ts/` only. The UI build is green because it consumes `@realmid/web-admin` (vendored) for api keys and doesn't use the token manager — but the shim is now behind. Re-sync `ui/sdk-ts` with `sdk/ts@0.13.0`.
- [ ] **Tag-naming doc fix** (a partner preflight item 1, 2026-05-27) — Go module tags use the **slash** form (`go/v0.13.0`), required for `go get github.com/Realm-ID/sdk/go`. CHANGELOG, `sdk/docs/realmid-answers-from-RI.md`, and the root `CLAUDE.md` status block cite the **hyphen** form (`go-v0.13.0`), which is a legacy one-off (`go-v0.10.0`) and misleads `go get`. Standardize docs to slash.
- [ ] **`quickstart.md` `NewVerifier` stale** (a partner preflight item 5) — says Go/Java expose `realmid.NewVerifier(...)`; Go has no exported `NewVerifier` (verification is `realm.Verify(ctx, token, opts)`). Fix the doc.
- [ ] **`@realmid/web` publish/tag status** (a partner preflight item 4) — packages are at `0.4.0` in the monorepo but the latest `web-*` git tag is `web-v0.3.0`, so `0.4.0` looks uncut/unpublished. Confirm npm publish + cut the matching tag; document the BFF-fronted SPA combo (`@realmid/web` + `@realmid/web-firebase` (+ `@realmid/web-react`)).
- [ ] **`@realmid/web-admin` version bump + re-vendor** (2026-05-28) — the api-key `apiKeys.{list,create,revoke}` methods were added and the UI's vendored tarball (`ui/web/vendor/realmid-web-admin-0.2.0.tgz`) was repacked **without** bumping the package version, so `0.2.0` now ships two different public APIs. Bump `sdk/web/packages/admin` → `0.3.0`, re-pack honoring the repack gotcha (`sdk/CLAUDE.md`: copy fresh `sdk/ts/dist` into the bundled `@realmid/sdk` before `npm pack`), re-vendor as `realmid-web-admin-0.3.0.tgz`, and point `ui/web/package.json` at it. UI build is currently green against the repacked 0.2.0 tarball; this is hygiene, not a functional break.
- [ ] Remaining HTTP→SDK surface gaps (lower priority, partner-facing): `GET /me` caller identity; tenant domain delete (`DELETE /platforms/{pid}/tenants/{tid}/domains/{domain}`); realm origin bind/detach (`POST` / `DELETE /platforms/{id}/origins[/{id}]`). Operator/base-realm surfaces (platform create/rename, `/admin/*` suspend/rotate/notes) are intentionally out of the partner SDK.
