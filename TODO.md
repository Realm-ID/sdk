# sdk/ — punch list

- [x] **ADR-051 platform-auth migration** (DONE 2026-05-28, `java-v0.10.0`) — `java/.../platformtoken/PlatformTokenManager.java` no longer calls the removed `POST /auth/platform-token` (hard-cut server-side in v0.7.0). Bootstraps via `POST /auth/login {grant_type:"platform_api_key"}` and refreshes via `POST /auth/token` (refresh token as bearer), falling back to a fresh login on 401 — mirrors the Go `sessionManager`. Public surface (`getToken()`/`invalidate()`) unchanged; `invalidate()` now preserves the refresh token. Tests in `PlatformTokenManagerTest` rewritten for the two-endpoint flow; `AuthClientTest`/`OriginsTest` bootstrap mocks migrated.
- [ ] `ts/src/auth.ts` — BFF on-behalf-of parity. The TS current-user session/MFA methods (`revokeSession`, `listSessions`, and the new `revokeAllSessions`/`enrollMfa`/`confirmMfa`/`disableMfa`, SPEC §4.5–4.10) accept only a direct `userBearer`; Go and Java also support BFF mode (`userId` + platform token + `X-On-Behalf-Of-User`). Add the on-behalf-of header path to the TS HttpClient + these methods for cross-language parity.
- [x] **Long-lived-client token manager** (SHIPPED 2026-05-28, SPEC §4.2.1) — `NewTokenManager`/`newTokenManager` + `RefreshSink` (persist-before-return) + single-flight live in `go/token_manager.go` and `ts/src/token-manager.ts`. Auth model: own API key → issuer direct (wraps `Auth.Token`). Java shipped 2026-05-28 (`java/.../auth/TokenManager.java`, `java-v0.10.0`).
- [x] **Typed dead-refresh error code** (SHIPPED 2026-05-28, SPEC §3.1) — single `refresh_invalid` emitted by issuer `/auth/token` (gToken maps `ErrNotAuthenticated`) and surfaced as `ErrCodeRefreshInvalid` / `"refresh_invalid"` in Go+TS. Not split into expiry/reuse (issuer doesn't distinguish on the wire). Requires issuer ≥ v0.12.0. Java shipped 2026-05-28 (`ErrorCode.REFRESH_INVALID`, `java-v0.10.0`).
- [x] **Java parity: token manager + refresh_invalid + api-key DTO** (DONE 2026-05-28, `java-v0.10.0`) — Java restored to v0.8.0 lockstep with Go/TS. Shipped: `ErrorCode.REFRESH_INVALID` (§3.1; the HTTP decoder already reads the nested `error.code`), `TokenManager` + `RefreshSink` + `TokenManagerOptions` via `auth().newTokenManager(...)` (§4.2.1 — cached token w/ 60s lead, single-flight, persist-before-return sink, `refresh_invalid` terminal), and the api-key DTO alignment (`APIKey {id,prefix,role,label?,value?,createdAt,lastUsedAt?,revokedAt?}` + `APIKey.revoked()`; `APIKeyCreate {scope,label?}`). The ADR-051 platform-token migration above was completed as a prerequisite. New tests: `TokenManagerTest`, `APIKeysClientTest`. Full suite 89/89 green.
- [x] **`ui/sdk-ts` drift** (2026-05-28; partial re-sync, structural blocker noted) — `ui/sdk-ts/` is described in `ui/CLAUDE.md` as a mirror of `sdk/ts/`, but in practice it is a **minimal JWT-verifier shim** (only `verifier.ts` + `admin.ts` types + `index.ts`). Its `verifier.ts` is the pre-`errors.ts` standalone variant (own `Config`/`Claims`/`VerifyError`); it does NOT import the `errors.ts` taxonomy, `auth.ts`, `http.ts`, `realm.ts`, or `claims.ts`. Consequently the v0.8.0 items have **no surface in the shim**: `refresh_invalid` lives in `errors.ts` (an auth-flow code, not a verifier code, and the shim has no errors file), and `TokenManager`/`auth` wiring/`api-keys` DTOs depend on the full auth/http/realm stack the shim doesn't carry. Bumped `ui/sdk-ts/package.json` 0.5.0 → 0.13.0; build + typecheck + tests (8/8) green; `ui/web` does NOT consume `ui/sdk-ts` at build time (only an OnboardVerified code-sample string references `@realmid/sdk`), so nothing downstream changed. **Remaining (needs design go-ahead — it is a structural rebuild, not a file copy):** decide whether the shim should become a full `sdk/ts` mirror (drag in errors/auth/http/realm/token-manager/api-keys) or whether `ui/CLAUDE.md`'s "mirror / do not let them drift" wording should be narrowed to "verifier + admin types only." Also: `ui/sdk-ts` verifier tests are mildly flaky (saw 1/8 intermittent fail, timing/JWKS-mock related, unrelated to the version bump).
- [ ] **Tag-naming doc fix** (a partner preflight item 1, 2026-05-27) — Go module tags use the **slash** form (`go/v0.13.0`), required for `go get github.com/Realm-ID/sdk/go`.
